# 애니메이션 뷰어 개발 기록

## 실행 방법

Python 3와 pico2d가 설치된 환경에서 저장소 루트 기준으로 실행한다.

```powershell
python Labs/LEC09/sonic_animation_viewer.py
```

VS Code에서 `sonic_animation_viewer.py`를 열고 Python 파일 실행 기능을 사용해도 된다. `sonic-sprite.png`는 코드와 같은 폴더에 둔다. 창 크기는 1200 × 800이며 캐릭터는 중앙에 4배 크기로 표시한다. Esc 또는 창 닫기로 종료한다.

## 최종 검증

- Python 3.13 및 설치된 pico2d에서 구문 검사와 실제 창 생성·이미지 로딩·그리기를 실행했다.
- 전체 76프레임의 잘라내기 좌표 변환, 중앙 `(600, 400)` 배치, 가로·세로 4배 출력 인수를 검증했다. 최대 출력 크기는 너비 160, 높이 180 픽셀이다.
- 원본 캐릭터 영역(y=39~468)의 불투명 픽셀 45,746개가 등록된 프레임에 정확히 한 번씩 포함됨을 확인했다. 누락 0개, 중복 0개였다.
- pico2d로 76프레임을 모아 렌더링한 검사용 이미지를 육안 확인했다. 잘림과 인접 프레임 혼입이 없었다. 이미지 상단 제목과 하단 제작자 표기·장식은 제외했다.
- 가상 시간으로 두 바퀴의 모든 프레임 순서, 반복 횟수, 정지 직전·직후 상태를 검증했다. 프레임 표시 구간 760회, 정지 20회, 합계 96초가 일치했다.
- 실제 pico2d 창에서도 두 바퀴를 재생했다. 소요 시간은 100.220초였고, 20회 정지 시간은 0.9994~1.0083초로 허용 오차 ±0.1초 안에 들어왔다.
- 실제 SDL 이벤트 큐에 Esc 및 창 닫기 이벤트를 넣어 재생 중·정지 중의 네 조합을 확인했다. 모두 0.25초 이내에 재생 루프가 종료되었다. 물리적인 키보드·마우스 조작 대신 이벤트 주입으로 검증했다.
- 이미지 누락 시 파일 경로를 포함한 오류를 확인했고, 디코딩 실패는 로더 예외를 주입하여 경로 안내 및 원인 예외 보존을 검증했다.
- 다른 폴더에서 실제 이미지 로딩에 성공했다. 과제 폴더 대상 `git diff --check`도 통과했다.

개발 중 검증용 스크립트와 프레임 미리보기는 제출용 실행 파일에 포함하지 않았다. 실행 코드는 `sonic_animation_viewer.py` 하나다.
